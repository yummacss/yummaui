# Writing

- **PR bodies**: one short block per topic under a bold heading, then the
  checks line. Say **what changed**, and nothing else. No cause, no history,
  no justification: a reader outside the project does not care why a thing was
  renamed from A to B. The why goes in the notes, the private `yummacss/notes`
  repo.
- **Commit messages**: a subject and a couple of lines. No essays.
- **Code comments**: one or two lines. A comment earns its length only where
  the code is genuinely surprising, and never by repeating the same paragraph
  in a dozen files.
- **No attribution footers** in commits or PRs. `.claude/settings.json` clears
  them; do not add them by hand either.
- The GitHub tool in cloud sessions appends a "Generated by Claude Code"
  session footer when it creates a PR. Re-save the body right after creating
  the PR; an edit does not add it back.
- No em dashes.
- Never name another framework to explain a Yumma decision.

# Copy

- The prose rules live in `packages/cli/src/copywriting.test.ts` and run over the strings
  `yummaui` prints. US spelling, no contractions, no em dashes, `cannot` as one
  word, one ellipsis character, never another framework's name, and focus draws an outline
  rather than a ring.
- The site holds its own copy in `apps/yummaui.com/tests/copywriting.test.ts`,
  run over its pages. Each package owns its rules rather than importing them.

# Working

- PRs, never direct commits to `main`.
- Verify an issue or a note against the code before acting on it. Most are
  right about the symptom and wrong about the cause.

# The site

`apps/yummaui.com` is yummaui.com: guides under `/docs`, components under
`/components`. Paths in this part are inside it.

## Writing for the site

- **PR bodies**: link every component you name to its page, with the link on
  the bold heading itself. While a branch is open the link is that branch's
  Vercel preview:
  `https://yummauicom-git-<branch>-rrenildopereiraas-projects.vercel.app/components/<id>`,
  where `<branch>` is the branch name with `/` as `-`. Once merged it is
  `https://www.yummaui.com/components/<id>`. The same rule applies in chat.
- **Docs pages are short.** The description is the lead, so the body opens
  with a heading, a reference table or a hint, never a paragraph. A paragraph
  stays under 30 words. `&` joins words in a list, `and` joins clauses.
  `tests/copywriting.test.ts` holds the first two.
- **Headings are sentence case**, and so are Step and admonition titles.
  Page titles stay Title Case. Contractions are fine in the site's pages.
- **Docs describe the current version only.** Present tense, no comparison
  with a past one.
- Focus draws an **outline**, never a ring.
- Base UI primitives over raw HTML; where a primitive renders a different
  element, that is its `render` prop. Raw tags are for layout, text, lists.
- A generated file opens with a comment naming the script that writes it.
  Never edit it by hand. `src/registry` is left out of `vp fmt`, so the
  components people install keep their layout.

## Content model

What the examples are _about_, which is a separate question from how the copy
is written.

- One world: a person looking after their own files and settings. Files,
  folders, documents, search, themes, shortcuts, formatting.
- No organisations. No teams, members, roles, invitations, plans, billing,
  invoices, subscriptions, sprints or boards. A component demo that needs a
  second person to make sense is the wrong demo.
- People appear only where the component is about a person: Avatar, Avatar
  Stack, Preview Card. One person, not a cast, and nowhere else.
- Icons name the thing they sit beside. An icon chosen for decoration is a
  content decision, not a visual one, and belongs to this list.
- `tests/content-model.test.ts` holds the mechanical half.

## Shape

- `square` is no radius, `squircle` is `br-xxl cs-s`, and `rounded` is the
  natural round for that control: `br-sm` on a checkbox, `br-lg` on a panel,
  `br-9999` on a switch or a track, which is already a capsule at that height.
- `rounded` is the default wherever a component has a shape. `square` is a
  choice, never the default.
- `pill` appears only where a smaller `rounded` also makes sense, so a
  component offering both keeps them different. Never add `pill` as a synonym.
- Shape is not a style axis where it is the affordance. A radio is round
  because round means _one of these_ and square means _any of these_, so it
  has no `shape` prop at all. Ask that question before adding one.
- `tests/registry.test.ts` holds the mechanical half.

## Look

- Flat: one border, no bevel, no gradient. Squircle is the default shape;
  a component can keep its own, as Avatar keeps `circle`.
- Colors are roles, not palette shades: `raised`, `well`, `field`, `fill`,
  `on-fill`, `label`, `hint`, `rim`, `shadow`, `line`, `check`, `on`, `knob`
  and `focus`, each a light and a Graphite pair in `src/utils/roles.mjs`. A
  component names roles only, so dark mode follows `color-scheme` with no
  class of its own. Role values are `oklch()`, which needs Yumma CSS 4.9.
- Surfaces and controls are `bg:raised bw:1 bc:rim`; fields are
  `bg:field bw:1 bc:rim`. Filled ones are `bg:fill bc:fill c:on-fill`, so the
  border disappears into any accent.
- Ticked, picked and highlighted are `check` on `bw:1 bc:transparent`, with
  `c:white`. An on switch is `on`, its thumb `knob`. Icons and shortcuts in a
  row are `o:70` of its color, so they turn white with it.
- Pressed in is an on/off that stays on by itself (Toggle, Toolbar): `bg:well`
  with `bc:rim`, no inset shadow. Picking one of several is a `raised` chip on
  a `well` track (Tabs, Toggle Group).
- Only popups cast a shadow: `bg:raised bc:line bs-o:xl`, `bs-o:md` for a
  tooltip. A scrim behind a dialog is `bg:shadow/30`. No `shadow` prop.
- A divider is one line: `h:0 btw:1 bc:line`, or `w:0 blw:1 bc:line`
  standing up.
- Focus is `fv:os:s fv:ow:3 fv:oo:0 fv:oc:focus/40 fv:bc:focus`: a soft
  outline and a darker border, both from the one role.
- Numbers that change in place (counters, values, sizes) are `fvn:tn`.
- A shortcut in a row (menus, tooltips) is plain text in the row's color,
  so it turns with a highlighted row: `fs:xs fw:400 lh:4 ff:d o:60`, pushed
  to the row's end in menus. In running text, Kbd draws a
  key 2px deep at the bottom: `btw:1 blw:1 brw:1 bbw:2 bc:rim`.
  `tests/registry.test.ts` holds both.
- Yumma sorts its rules by name, so `bw:` beats `bbw:` and `bc:` beats `bbc:`.
  A border that differs by side names every side.

## Prop order

- A component's own props come first, in whatever order reads best for that
  component. The props every component shares follow, in one fixed sequence:
  style, then state, then behavior, then the escape hatches. `shape` sits
  after `size` on all 33 components that have it.
- The sequence lives in `SHARED_PROP_ORDER` in `src/utils/props.ts`, the only
  place to change it. `node scripts/order-props.mjs` re-sorts every schema to
  match, and `tests/registry.test.ts` fails when one drifts.

## Carried styles

- Style and Radius set the look of every component and of the code copied:
  `style` and `radius` in the URL, remembered in `localStorage` for the next
  page, and the address wins. `src/utils/styles.mjs` owns them. A blocked
  pair in an address falls back to the nearest allowed radius.
- **Component pages are rows**, not files: `src/utils/component-pages.mjs`
  holds one per page and `src/utils/uis.ts` merges them with the MDX pages.
  A page with prose of its own is an MDX file instead.
- **Blocks live under `/blocks`**: a section in `src/config/sidebar.ts` with
  `area: "blocks"` puts its pages there; the sidebar lists them like any
  other section.
- Every component page shows its Example, a `scene` in its meta, with the
  Component API table under it listing every prop. `tests/registry.test.ts`
  fails a meta without one. `resizable: true` on a row lets the preview drag
  to phone & tablet widths, for whole screen regions.

## Accent

- The accent recolours the **preview** and nothing anyone installs. It works by
  redefining the classes the components name, inside the preview frame only, so
  the Code tab stays byte-identical when it changes.
- `src/utils/accent.ts` holds the one table that drives both the CSS and the
  guard. A component that names a new `slate-11` or `slate-12` class fails
  `tests/accent.test.ts` until the table covers it.
- `c-slate-12` is a label on white, not a control, so it is never part of it.
- It lives in `localStorage`, never the URL: an address states what the
  component is, and the accent changes nothing about it.

## Page chrome

- Every page opens with `SkipLink` and has one `<main id="main">`, so the first
  Tab skips the navbar and the sidebar.
- No tooltips on the site's own controls, and no `title` attributes for them.
  A control's accessible name is its `aria-label`. An `<iframe title>` is that
  frame's accessible name, not a tooltip, and stays.
- Bounded scrolling goes through `Scroller`, which is Base UI's Scroll Area
  with the site's own scrollbar. Two traps it works around: the scroll area's
  root sets `position: relative` inline, which beats a `p-st` class, so the
  positioning lives on a wrapper; and every box down to the viewport needs
  `f-1 min-h-0`, because a viewport on `h-100%` under a `max-height` parent
  grows to its content and never scrolls.
- The scrollbar is 12px and square, sits above sticky headers (`zi:20`), and
  fades with `hovering:` and `scrolling:`, two states in `yummacss.config.mjs`.
- Registry icons are Tabler, from `@tabler/icons-react`: filled for objects,
  outline for marks, arrows and operators. A component whose objects lack a
  filled half draws them all outline. `tests/icons.test.ts` holds it.
- Site icons come from `src/icons.tsx`, Tabler outline at a 1.5 stroke; the
  notes, "Icons at 16px", have the measurements.

## Motion

- The registry animates with Yumma classes and ships no CSS of its own.
  `opening:` and `closing:` for what Base UI marks, `@st:` for an element
  that is inserted or re-keyed, `an:` for a loop, and `@prm:` to stop each.
- Every state and keyframe a component uses is one the Yumma UI installation
  page tells people to add. `tests/motion.test.ts` holds the page, the site
  config and the registry to the same names.
